## 演習1の解答・解説（同値分割法 ＆ 境界値分析）

### 解答
1. **同値分割法（計5パーティション）：**
   - **有効パーティション（3つ）：**
     - `1〜9個`（代表値の例：`5`）
     - `10〜49個`（代表値の例：`25`）
     - `50〜99個`（代表値の例：`70`）
   - **無効パーティション（2つ）：**
     - `0個以下`（代表値の例：`0`, `-1`）
     - `100個以上`（代表値の例：`100`）
     - ※数値以外（空欄・小数・文字列）が入力可能なUIなら、それも無効パーティションに追加します。
2. **2値BVAのテストデータ（計8個）：**  
   `0`, `1`, `9`, `10`, `49`, `50`, `99`, `100`

> **新人QAへのポイント**  
> 現場では「10個以上」をエンジニアが誤って `> 10`（11個以上）と実装するミスが頻発します。また、無効値の「0個」「100個」でボタンが非活性になるか、エラーメッセージが正しく出るかを確認するのが重要です。より厳密な3値BVAを行う場合は、各境界の両隣（`2`, `8`, `11`, `48`, `51`, `98` 等）も追加します。

## 演習2の解答・解説（デシジョンテーブルテスト）

### 解答
討伐失敗時は他の条件が結果に影響しないため `-（無関係）` として1列に統合でき、全5ルールで100%網羅できます。

| 条件／アクション（レイドボス報酬） | R1 | R2 | R3 | R4 | R5 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 条件1：討伐に成功した | T | T | T | T | F |
| 条件2：与ダメージ10%以上 | T | T | F | F | - |
| 条件3：報酬ブースト薬を使用 | T | F | T | F | - |
| **アクション：参加賞を付与** | | | | | **X** |
| **アクション：討伐報酬（通常）を付与** | | **X** | | **X** | |
| **アクション：討伐報酬（2倍）を付与** | **X** | | **X** | | |
| **アクション：MVPボーナスを付与（通常1倍）** | **X** | **X** | | | |

> **新人QAへのポイント**  
> 仕様書を文章のまま読むと「討伐失敗時にブースト薬は消費されるのか？」「ブースト薬使用時にMVPボーナスはどうなるのか？」といった仕様の抜け漏れや曖昧さに気づきにくいですが、表に起こすことでプランナーへ事前に質問できるようになります（シフトレフトの実践）。

## 演習3の解答・解説（状態遷移テスト）

### 解答
1. **確認すべき無効な遷移の例：**
   - **「受取済」状態で再度「受取ボタン」を押下**（連打・通信遅延時の再送含む）：報酬が二重付与されないこと。
   - **「期限切れ」状態で「受取ボタン」を押下**（期間終了直前に開いた画面のまま操作）：エラーになり報酬が受け取れないこと。
   - **「未達成」状態で「受取ボタン」を押下**：ボタンが押せない（または無効）こと。
2. **1テストケースにつき無効な遷移を1つにする理由：**  
   **欠陥のマスキング**（あるバグが原因でテストが止まったり異常な状態になったりして、別の無効遷移に潜むバグの発見を妨げてしまう現象）を防ぐためです。

> **新人QAへのポイント**  
> ソーシャルゲームでは「期間終了の1秒前に画面を開いておき、終了後にボタンを押す」ような**境界時刻 × 無効遷移**の操作で重大な不具合（不正なアイテム取得など）が起きやすいため、状態表を作って無効セルを必ず潰す習慣をつけましょう。
